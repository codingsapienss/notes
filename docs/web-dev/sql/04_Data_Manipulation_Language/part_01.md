# INSERT Operations

## 1. Introduction to INSERT

`INSERT` is a DML (Data Manipulation Language) command used to add new records (rows) into a table.

It supports:

- Inserting a single row.
- Inserting multiple rows.
- Inserting values into selected columns.
- Inserting default values.
- Inserting data from another table.
- Returning inserted records using `RETURNING`.

---

## 2. Basic INSERT Syntax

```sql
INSERT INTO table_name (column1, column2, column3)
VALUES (value1, value2, value3);
```

Example:

```sql
INSERT INTO departments (department_name)
VALUES ('Engineering');
```

Verify:

```sql
SELECT * FROM departments;
```

**Important:** The values must match the corresponding column order and data types.

---

## 3. INSERT with Specific Columns

You do not need to provide values for every column.

Example:

```sql
INSERT INTO employees (
    first_name,
    last_name,
    email,
    department_id,
    status
)
VALUES (
    'Rahul',
    'Sharma',
    'rahul@example.com',
    1,
    'active'
);
```

PostgreSQL handles omitted columns as follows:

| Column definition        | Behaviour when omitted          |
| ------------------------ | ------------------------------- |
| Has DEFAULT              | Uses the default value          |
| Identity column          | Generates a value automatically |
| Nullable column          | Inserts NULL                    |
| NOT NULL without DEFAULT | Raises an error                 |

**Important:** Explicitly passing `NULL` is different from omitting a column. A default value is not applied when you explicitly insert `NULL`.

---

## 4. INSERT Without Specifying Column Names

You can insert values without listing column names:

```sql
INSERT INTO departments
VALUES (4, 'Marketing');
```

However, values must be supplied in the exact table column order.

This approach is fragile because adding or changing columns can break the query.

**Best practice:** Specify column names explicitly.

```sql
INSERT INTO departments (department_id, department_name)
VALUES (4, 'Marketing');
```

---

## 5. INSERT Multiple Rows

You can insert multiple records using one `INSERT` statement.

### Syntax

```sql
INSERT INTO table_name (column1, column2)
VALUES
    (value1, value2),
    (value3, value4),
    (value5, value6);
```

### Example

```sql
INSERT INTO departments (department_name)
VALUES
    ('Sales'),
    ('Support'),
    ('Warehouse');
```

This inserts three records using one SQL statement.

### Insert multiple employees

```sql
INSERT INTO employees (
    first_name,
    last_name,
    email,
    department_id,
    status
)
VALUES
    ('Amit', 'Verma', 'amit@example.com', 1, 'active'),
    ('Priya', 'Singh', 'priya@example.com', 2, 'active'),
    ('Neha', 'Gupta', 'neha@example.com', 3, 'inactive');
```

All rows must provide compatible values for the specified columns.

---

## 6. INSERT with DEFAULT

PostgreSQL supports the `DEFAULT` keyword to explicitly request a column's default value.

Example:

```sql
INSERT INTO employees (
    first_name,
    last_name,
    email,
    status
)
VALUES (
    'Rohit',
    'Kumar',
    'rohit@example.com',
    DEFAULT
);
```

If `status` has a default value, PostgreSQL uses it.

### DEFAULT for an identity column

```sql
INSERT INTO departments (
    department_id,
    department_name
)
VALUES (
    DEFAULT,
    'Operations'
);
```

The identity column generates its value automatically.

### Insert only default values

```sql
INSERT INTO some_table
DEFAULT VALUES;
```

This inserts one row using the default value for every column.

It succeeds only if the table's defaults, identity definitions, and nullable columns satisfy all constraints.

---

## 7. INSERT and Auto-Generated IDs

PostgreSQL supports identity columns and the older `SERIAL` shorthand.

Example table:

```sql
CREATE TABLE customers (
    customer_id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    customer_name VARCHAR(100) NOT NULL,
    email VARCHAR(150) UNIQUE
);
```

Insert without specifying the ID:

```sql
INSERT INTO customers (customer_name, email)
VALUES ('Rahul Sharma', 'rahul@example.com');
```

PostgreSQL generates `customer_id` automatically.

### GENERATED ALWAYS vs GENERATED BY DEFAULT

**GENERATED ALWAYS**

```sql
customer_id BIGINT GENERATED ALWAYS AS IDENTITY
```

PostgreSQL normally rejects explicitly supplied identity values.

To override this:

```sql
INSERT INTO customers (
    customer_id,
    customer_name,
    email
)
OVERRIDING SYSTEM VALUE
VALUES (
    100,
    'Amit Sharma',
    'amit@example.com'
);
```

**GENERATED BY DEFAULT**

```sql
customer_id BIGINT GENERATED BY DEFAULT AS IDENTITY
```

PostgreSQL generates an ID when the column is omitted, but allows an explicitly supplied value.

Example:

```sql
INSERT INTO customers (
    customer_id,
    customer_name,
    email
)
VALUES (
    100,
    'Amit Sharma',
    'amit@example.com'
);
```

Use explicit IDs carefully. Manually inserting values does not automatically advance the associated identity sequence to match the highest inserted ID.

## 8. INSERT with RETURNING

PostgreSQL provides `RETURNING` to retrieve values from inserted rows.

This is particularly useful in backend applications.

### Return the generated ID

```sql
INSERT INTO customers (customer_name, email)
VALUES ('Rahul Sharma', 'rahul@example.com')
RETURNING customer_id;
```

Example result:

| customer_id |
| ----------: |
|         101 |

### Return the complete inserted record

```sql
INSERT INTO customers (customer_name, email)
VALUES ('Priya Singh', 'priya@example.com')
RETURNING *;
```

### Return selected columns

```sql
INSERT INTO employees (
    first_name,
    last_name,
    email,
    status
)
VALUES (
    'Amit',
    'Verma',
    'amit@example.com',
    DEFAULT
)
RETURNING employee_id, email, status;
```

### Why RETURNING matters in Node.js

Without `RETURNING`, an application may need another query to retrieve the generated ID.

With `RETURNING`, the insert and retrieval happen in one SQL statement.

Example using Node.js and `pg`:

```javascript
const result = await pool.query(
  `INSERT INTO customers (customer_name, email)
     VALUES ($1, $2)
     RETURNING customer_id, customer_name, email`,
  ["Rahul Sharma", "rahul@example.com"],
);

console.log(result.rows[0]);
```

## 9. INSERT Using SELECT

You can insert records from another table or query result.

This is useful for:

- Migrating data.
- Copying records.
- Archiving records.
- Creating derived datasets.

### Syntax

```sql
INSERT INTO target_table (column1, column2)
SELECT column1, column2
FROM source_table
WHERE condition;
```

### Example

Suppose you want to copy inactive employees into an archive table.

First, create the archive table:

```sql
CREATE TABLE employee_archive (
    employee_id BIGINT,
    first_name VARCHAR(100),
    last_name VARCHAR(100),
    email VARCHAR(150)
);
```

Insert matching employees:

```sql
INSERT INTO employee_archive (
    employee_id,
    first_name,
    last_name,
    email
)
SELECT
    employee_id,
    first_name,
    last_name,
    email
FROM employees
WHERE status = 'inactive';
```

**Important:** The number and order of selected columns must match the target column list, and their data types must be compatible.

### INSERT from another table without WHERE

```sql
INSERT INTO employee_archive (
    employee_id,
    first_name,
    last_name,
    email
)
SELECT
    employee_id,
    first_name,
    last_name,
    email
FROM employees;
```

This copies every selected employee record.

## 10. INSERT with Constraints

When inserting data, PostgreSQL checks the table's constraints.

For example:

```sql
CREATE TABLE products (
    product_id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    product_name VARCHAR(100) NOT NULL,
    price NUMERIC(10, 2) CHECK (price >= 0),
    sku VARCHAR(50) UNIQUE
);
```

### NOT NULL violation

```sql
INSERT INTO products (price, sku)
VALUES (500, 'SKU-101');
```

Fails because `product_name` is required.

### CHECK violation

```sql
INSERT INTO products (product_name, price, sku)
VALUES ('Laptop', -500, 'SKU-102');
```

Fails because the price cannot be negative.

### UNIQUE violation

```sql
INSERT INTO products (product_name, price, sku)
VALUES
    ('Keyboard', 1000, 'SKU-101');
```

If `SKU-101` already exists, the insert fails.

### PRIMARY KEY violation

```sql
INSERT INTO products (product_id, product_name, price, sku)
OVERRIDING SYSTEM VALUE
VALUES (1, 'Mouse', 500, 'SKU-103');
```

If product ID `1` already exists, PostgreSQL raises a primary-key violation.

### FOREIGN KEY violation

```sql
INSERT INTO employees (
    first_name,
    last_name,
    email,
    department_id,
    status
)
VALUES (
    'Aman',
    'Shah',
    'aman@example.com',
    9999,
    'active'
);
```

If department `9999` does not exist, the insert fails when `department_id` references `departments`.

## 11. INSERT and NULL

`NULL` represents a missing or unknown value. It is not the same as zero or an empty string.

Example:

```sql
INSERT INTO customers (
    customer_name,
    email
)
VALUES (
    'Aman Sharma',
    NULL
);
```

This succeeds only if `email` permits NULL.

### Empty string vs NULL

```sql
INSERT INTO customers (customer_name, email)
VALUES
    ('Rahul', ''),
    ('Priya', NULL);
```

| Value  | Meaning                  |
| ------ | ------------------------ |
| `''`   | Empty string             |
| `NULL` | Missing or unknown value |

They are different values in PostgreSQL.

---

## 12. INSERT with Schema Name

If a table belongs to a particular schema, you can specify the schema explicitly.

```sql
INSERT INTO public.departments (department_name)
VALUES ('Engineering');
```

General syntax:

```sql
INSERT INTO schema_name.table_name (column1)
VALUES (value1);
```

This avoids ambiguity when tables with the same name exist in different schemas.

## 13. INSERT and Transactions

An insert can be executed inside a transaction.

### Example

```sql
BEGIN;

INSERT INTO customers (customer_name, email)
VALUES ('Rahul Sharma', 'rahul@example.com');

-- Check the inserted record.
SELECT *
FROM customers
WHERE email = 'rahul@example.com';

COMMIT;
```

To undo the insert:

```sql
BEGIN;

INSERT INTO customers (customer_name, email)
VALUES ('Amit Sharma', 'amit@example.com');

ROLLBACK;
```

The inserted record is rolled back.

### Important

In a transaction, an error can put the transaction into an aborted state. You must roll back to continue using the transaction, unless you have used a savepoint and recover with `ROLLBACK TO SAVEPOINT`.

## 14. Common INSERT Errors

| Error                      | Cause                                             |
| -------------------------- | ------------------------------------------------- |
| Duplicate key violation    | Duplicate PRIMARY KEY or UNIQUE value             |
| NOT NULL violation         | Missing required value                            |
| Foreign key violation      | Referenced record does not exist                  |
| Check constraint violation | Value fails a CHECK condition                     |
| Invalid input syntax       | Value cannot be converted to the target data type |
| Too many values            | More values supplied than target columns          |
| Not enough values          | Missing values for explicitly listed columns      |

### Example: Invalid data type

```sql
INSERT INTO products (product_name, price)
VALUES ('Laptop', 'expensive');
```

If `price` is numeric, PostgreSQL rejects the value.

## 15. Best Practices for Backend Developers

1. **Always specify column names.** Avoid depending on physical table column order.
2. **Use parameterized queries.** Never concatenate user input directly into SQL.
3. **Use RETURNING.** Retrieve generated IDs without an additional query.
4. **Use transactions for related operations.** Keep logically connected writes consistent.
5. **Validate input.** Do not rely exclusively on frontend validation.
6. **Respect constraints.** Database constraints provide protection even when multiple applications access the database.
7. **Use multi-row INSERT when appropriate.** It can reduce the overhead of issuing many individual statements.
8. **Handle errors.** Account for duplicate keys, foreign-key violations, and invalid values.

### Unsafe query

```javascript
const query = `
    INSERT INTO customers (customer_name, email)
    VALUES ('${name}', '${email}')
`;
```

This is vulnerable to SQL injection.

### Safe parameterized query

```javascript
const result = await pool.query(
  `INSERT INTO customers (customer_name, email)
     VALUES ($1, $2)
     RETURNING customer_id`,
  [name, email],
);
```

PostgreSQL receives the SQL statement and parameter values separately.

## 17. Interview Questions

**Q1. What is INSERT in SQL?**

A DML command used to add new records to a table.

**Q2. Can we insert multiple rows in one query?**

Yes, using multiple value groups in a single `VALUES` clause.

**Q3. What happens if we omit a column during INSERT?**

PostgreSQL uses its default value, generates an identity value, or inserts NULL if allowed. Otherwise, it raises an error.

**Q4. What is the difference between DEFAULT and NULL?**

`DEFAULT` requests the column's configured default expression. `NULL` explicitly supplies a null value.

**Q5. What is RETURNING in PostgreSQL?**

It returns values from rows inserted by the statement, including generated IDs.

**Q6. Can we insert data from one table into another?**

Yes, using `INSERT INTO ... SELECT`.

**Q7. What happens if a FOREIGN KEY constraint is violated?**

PostgreSQL rejects the insert unless the constraint is deferred and satisfied before the relevant constraint check.

**Q8. What is the difference between GENERATED ALWAYS and GENERATED BY DEFAULT?**

- `ALWAYS`: Explicit identity values are normally rejected unless overridden.
- `BY DEFAULT`: Explicit values are accepted.

**Q9. Does PostgreSQL automatically generate IDs for SERIAL and IDENTITY columns?**

Yes, when the column is omitted or `DEFAULT` is specified.

**Q10. Why should backend developers use parameterized INSERT queries?**

They separate SQL code from user-supplied values, helping prevent SQL injection and handling values safely.

---

## Key Takeaways

- `INSERT INTO ... VALUES` adds records.
- Multiple rows can be inserted in one statement.
- Omitted columns use defaults, identity generation, or NULL where permitted.
- `DEFAULT` and explicit `NULL` are different.
- `RETURNING` retrieves generated values and inserted records.
- `INSERT INTO ... SELECT` copies query results into another table.
- Constraints are enforced during insertion.
- Use parameterized queries in Node.js applications.
- Use transactions when multiple database operations must succeed or fail together.
